# 【第一回】量子回路プログラミング講座：可能性をプログラムするとは何か？

生成AIがコードを書く時代になりました。

関数名を考え、構文を調べ、定型コードを手で入力する仕事は、これからますますAIへ移っていくでしょう。では、人間のプログラマーには何が残るのでしょうか。

私は、重要になるのは「コードを何文字書けるか」ではなく、**何を計算させたいかを考え、その結果が正しいか判断する力**だと思っています。

そのためには、今までと違う計算の仕組みを知っておく価値があります。その一つが量子回路です。

ただし、この連載は「有名な量子アルゴリズムを暗記して、専門家と同じ答えを言えるようになろう」という講座ではありません。

量子回路が何を操作できるのかを自分の目で確かめ、そこから、まだ教科書に載っていない使い方を考えるための連載です。実装方法が分からなければ、AIにコードを書かせればいい。けれども、AIへ何を頼むか、出てきた回路が何をしているかは、人間が判断しなければなりません。

今回は、その最初の一歩として、量子回路を「可能性をプログラムする仕組み」として触ってみます。

---

## まずはアプリを開こう

この連載では、量子回路学習アプリ **BlochCraft** を使います。

**[BlochCraftを開く](https://awakeningos.github.io/blochcraft/)**

インストールは不要です。ブラウザーでそのまま動きます。

画面には球体、3量子ビット回路エディター、可能性の表、測定ラボ、Qiskitコードなどが表示されます。最初から全部を理解する必要はありません。

今回使うのは、主に次の2か所です。

- 「3量子ビット回路エディター」
- その下にある「可能性の表」

量子ビットはA・B・Cの3個ありますが、第1回ではAだけを操作します。BとCは、そのままにしておきます。

---

## 何もしなければ、可能性は一つだけ

最初は回路に何も置かれていません。

可能性の表を見ると、初期状態は一つに決まっています。A・B・Cはすべて0です。

これは普通のプログラムで、3個のビットを次のように初期化した状態に近いものです。

```text
A = 0
B = 0
C = 0
```

まだ不思議なことは起きていません。

大切なのは、量子回路も最初から曖昧なわけではないということです。何も操作していない初期状態では、測定結果は確定しています。

では、この確定した値を変えてみましょう。

---

## 実験1：Xで「0を1に変える」

回路エディターの上にある **X** ボタンを選び、Aの1列目をクリックしてください。

可能性の表が変わり、Aが1、BとCが0の状態だけが100%になります。

Xゲートがしたことは単純です。

```text
0 → 1
1 → 0
```

古典プログラムのNOTに近い操作です。

球体では、Aの状態が北の `|0⟩` から南の `|1⟩` へ移ります。Xゲートは、球体を東西軸の周りに180度回転させます。

ここでは、可能性は増えていません。

操作前は「0になる可能性が100%」、操作後は「1になる可能性が100%」。確定している答えを反転しただけです。

つまりXは、**決まっている値を別の決まった値へ変えるプログラム**です。

いったん「全部消す」を押して、回路を初期状態へ戻してください。

---

## 実験2：Hで「二つの可能性を作る」

次は **H** ボタンを選び、Aの1列目をクリックします。

可能性の表を見ると、今度は結果が一つに決まりません。

Aが0の結果と、Aが1の結果が、それぞれ50%になります。BとCは0のままです。

```text
A = 0 になる可能性：50%
A = 1 になる可能性：50%
```

HはHadamard（アダマール）ゲートと呼ばれます。

重要なのは名前ではありません。Xとの違いです。

- Xは、確定した0を確定した1へ変えた
- Hは、0と1の二つの可能性を持つ状態を作った

球体では、Aの白い矢印が北から東へ移ります。北でも南でもない位置です。

この状態を、量子力学では重ね合わせと呼びます。

数式では次のように表します。

\[
H|0\rangle=\frac{|0\rangle+|1\rangle}{\sqrt{2}}
\]

初回から数式を暗記する必要はありません。ここでは、次の意味だけ掴めれば十分です。

> Hは、0か1のどちらかへすぐ決めるのではなく、後の処理に使える二つの可能性を作る。

量子回路プログラミングの面白さは、乱数を一つ取り出すことではありません。この「まだ結果になっていない可能性」に、さらに別の操作を加えられることです。

---

## 50%ずつなら、ただのコイントスでは？

ここで当然、疑問が出ます。

「0と1が50%ずつなら、普通の乱数やコイントスと何が違うのか？」

測定結果だけを一度見れば、確かに区別しにくいでしょう。

しかし、Hで作った状態は、単に「答えをまだ知らない」状態ではありません。0と1の成分を持ち、その間には位相という関係があります。

この違いを、もう一つの短い実験で確認できます。

---

## 実験3：Hをもう一度かける

Aの2列目にもHを置いてください。

回路は次のようになります。

```text
A: ──H──H──
```

1個目のHの後では、0と1が50%ずつでした。

ところが2個目のHの後では、Aは再び0へ戻ります。可能性の表でも、初期状態が100%になります。

もし1個目のHが、単純にコインを投げて0か1を決めていたなら、2個目のHだけで必ず0へ戻すことはできません。

戻れたのは、測定前の状態に「0と1が何%あるか」だけでなく、それらがどう組み合わされているかという情報も残っていたからです。2個目のHは、その成分を再び重ね合わせ、0側では強め合い、1側では打ち消し合わせます。

これが干渉です。

量子回路は、可能性を作るだけではありません。

> 可能性同士が、後で強め合ったり打ち消し合ったりするように設計できる。

ここが、普通の確率プログラムとの大きな違いです。

位相と干渉は次回以降に詳しく扱います。今回は「50%ずつと表示されていても、内部の状態まで同じとは限らない」と覚えておいてください。

---

## 「可能性をプログラムする」とはどういうことか

ここまでの3実験を整理します。

| 回路 | 起きたこと |
|---|---|
| 何もしない | Aは0に確定 |
| X | Aを0から1へ反転 |
| H | Aに0と1の可能性を作る |
| H → H | 可能性を干渉させ、Aを0へ戻す |

量子回路で扱う「可能性」は、最後にサイコロを振るための確率表ではありません。

測定する前なら、可能性の成分へさらにゲートを作用させられます。成分を増やす、回転させる、位相を変える、別の量子ビットと関係づける、そして最後にどの方向から測るかを決める。

量子回路を書くとは、こうした変化の順序を設計することです。

古典プログラムでは、値を順番に更新します。

```text
x = 0
x = not x
```

量子回路では、確定値だけでなく、測定前の状態そのものを操作します。

```text
初期状態を作る
可能性を作る
可能性の関係を変える
干渉させる
測定する
```

この新しい操作対象を理解することが、量子回路プログラミングの第一歩です。

---

## アプリの回路は、そのままQiskitコードになる

BlochCraftの下部には「回路からQiskitコードへ」という欄があります。

AへHを1個置いた場合、重要な部分は次の1行です。

```python
qc.h(0)
```

Xなら次のようになります。

```python
qc.x(0)
```

Hを2回置けば、同じ操作が2行並びます。

```python
qc.h(0)
qc.h(0)
```

今日の段階で、Qiskitのクラスや実行環境をすべて覚える必要はありません。

まずは、画面上で作った操作とコードの1行が対応していることを確認してください。

回路の意味を理解できていれば、構文はAIに書かせられます。しかし意味を知らなければ、AIが出した `qc.h(0)` が必要な操作なのか、余計な操作なのかを判断できません。

この連載が目指しているのは、コードを一字一句暗記することではなく、**AIが生成した回路の意図を読めること**です。

---

## AIへ頼むなら、何を伝えるべきか

今回の実験をAIへ依頼するなら、単に「量子コードを書いて」と頼むより、目的と確認したい結果を伝えます。

例えば、次のような依頼です。

```text
3量子ビットのQiskit回路を作ってください。
初期状態は |000⟩ です。
AにHadamardゲートを適用し、Aが0と1になる確率を確認したいです。
次にAへもう一度Hadamardゲートを適用し、|000⟩へ戻ることも確認してください。
各段階の状態ベクトルと測定確率を表示してください。
```

この依頼には、次の情報が入っています。

- 量子ビット数
- 初期状態
- どの量子ビットへ何をするか
- 何を観測したいか
- 途中結果も確認したいこと

ここまで言語化できれば、AIはかなり正確にコードを書けます。そして自分でもBlochCraftを使って、出力された回路が意図どおりか確認できます。

AI時代に必要なのは、すべてを手書きする能力だけではありません。

> 作りたい挙動を定義し、AIへ伝え、結果を検証する能力です。

---

## 今日の実験から、自分の用途を考える

ここで、既存の量子アルゴリズムの名前を覚える前に、一度自分の領域へ引き寄せて考えてみてください。

- 複数の可能性を、すぐ一つに決めず保持したい場面はあるか
- 後の条件によって、可能性を強めたり消したりしたい場面はあるか
- 結果だけでなく、可能性同士の関係を操作したい問題はあるか
- 自分の仕事、ゲーム、音楽、デザイン、探索、意思決定で、この考え方を試せないか

もちろん、思いついた用途がそのまま量子優位を生むとは限りません。現在の量子コンピューターには規模、ノイズ、入出力など多くの制約があります。

それでも、最初から既存用途だけを正解として覚える必要はありません。

仕組みを理解し、自分の問題を持ち込み、小さな回路で試し、AIと一緒に検証する。その過程から、新しい使い方が生まれる可能性があります。

---

## 第1回のまとめ

今回覚えてほしいのは、ゲートの一覧ではなく次の4点です。

1. Xは、確定した0と1を反転する。
2. Hは、測定前の状態に0と1の可能性を作る。
3. Hを2回かけると元へ戻る。量子状態は単純なコイントスではない。
4. 量子回路は、可能性とその組み合わせ方を操作するプログラムである。

次回は、今回最後に出てきた疑問を掘り下げます。

> 同じ「0と1が50%ずつ」でも、なぜ後の結果が変わるのか。

鍵になるのは、確率表だけでは見えない「位相」です。

BlochCraftで球体を回しながら、位相がどこにあり、どうやって計算結果へ戻ってくるのかを確かめます。
